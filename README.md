# Enterprise RAG Assistant

A secure, enterprise-grade AI assistant powered by Retrieval-Augmented Generation (RAG) with role-based access control, multi-source document retrieval, and explainable answers.

## Features

- **Intelligent Retrieval** - Semantic search (vector embeddings), keyword search (BM25), and hybrid retrieval with Reciprocal Rank Fusion
- **Secure Access Control** - JWT authentication with 6 role levels (admin, hr, finance, it_admin, manager, employee) enforcing document-level RBAC
- **Accurate Answers** - Grounded responses generated by Llama 3.3 70B via Groq, answering only from retrieved context
- **Explainability** - Source citations with relevance scores, confidence indicators, and retrieval trace showing routing decisions
- **Multi-Source Support** - Queries across PDFs, CSVs, JSON logs, and policy documents with automatic metadata tagging
- **Audit Trail** - Every query logged with user, resources accessed, and confidence score

## Architecture

```
React Frontend (3000) --> Node.js Backend (5000) --> Python AI Service (8000)
                              |                           |
                           MongoDB                     ChromaDB
                        (Users, Logs)              (Vector Embeddings)
```

See [ARCHITECTURE.md](ARCHITECTURE.md) for detailed system design, data flow, and RBAC matrix.

## Quick Start

### Prerequisites

- Node.js 18+
- Python 3.10+
- MongoDB 7+
- Groq API key (free at [console.groq.com](https://console.groq.com))

### 1. Clone and Install

```bash
# Backend
cd backend
npm install

# Frontend
cd ../frontend
npm install

# AI Service
cd ../ai-service
pip install -r requirements.txt
```

### 2. Configure Environment

```bash
# backend/.env
PORT=5000
MONGODB_URI=mongodb://localhost:27017/enterprise-rag
JWT_SECRET=your_secret_key_here
JWT_EXPIRE=7d
AI_SERVICE_URL=http://localhost:8000

# ai-service/.env
AI_SERVICE_PORT=8000
LLM_PROVIDER=groq
GROQ_API_KEY=your_groq_api_key
GROQ_MODEL=llama-3.3-70b-versatile
CHROMA_PERSIST_DIR=./chroma_db
EMBEDDING_MODEL=all-MiniLM-L6-v2
```

### 3. Seed Database

```bash
cd backend
node src/utils/seedUsers.js
```

### 4. Start Services

```bash
# Terminal 1: MongoDB
mongod --dbpath /data/db

# Terminal 2: Backend (port 5000)
cd backend && npm run dev

# Terminal 3: AI Service (port 8000)
cd ai-service && python main.py

# Terminal 4: Frontend (port 3000)
cd frontend && npm start
```

### 5. Open Browser

Navigate to `http://localhost:3000` and sign in or create an account.

## API Endpoints

### Authentication
| Method | Endpoint          | Description          | Auth |
|--------|-------------------|----------------------|------|
| POST   | /api/auth/signup  | Register new user    | No   |
| POST   | /api/auth/login   | Login, returns JWT   | No   |
| GET    | /api/auth/me      | Get current user     | Yes  |

### Query
| Method | Endpoint            | Description              | Auth |
|--------|---------------------|--------------------------|------|
| POST   | /api/query          | Submit RAG query         | Yes  |
| GET    | /api/query/history  | Get user's query history | Yes  |

### Admin (admin role only)
| Method | Endpoint              | Description            | Auth  |
|--------|-----------------------|------------------------|-------|
| POST   | /api/admin/ingest     | Re-index documents     | Admin |
| GET    | /api/admin/audit-logs | View all audit logs    | Admin |
| GET    | /api/admin/stats      | System statistics      | Admin |

## How RBAC Works

Each document chunk is tagged with metadata:
```json
{
  "source": "employees.csv",
  "department": "HR",
  "access_level": "hr",
  "doc_type": "csv_data"
}
```

When a user queries, the backend builds a metadata filter based on their role. ChromaDB applies this filter during vector search, ensuring users only see documents they're authorized to access.

**Example:** An `employee` querying "server outage incidents" receives results from general policies only, while an `it_admin` making the same query gets actual server logs and incident response plans.
